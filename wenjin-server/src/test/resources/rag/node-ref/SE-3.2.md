## 概念
用例图（Use Case Diagram）是 UML 中用于描述系统功能与外部参与者交互关系的视图。它从用户视角刻画“谁”在系统边界外发起“什么”业务目标，而不展开内部算法细节。典型元素包括参与者（Actor）、用例（Use Case）、系统边界以及关联、包含、扩展与泛化关系。参与者可以是人、外部系统或设备；用例是系统对外提供的、对参与者有价值的功能单元。用例图帮助干系人在需求早期对齐范围，避免把界面控件或内部模块误当作需求本身。

## 关键要点
画用例图时先划定系统边界，再枚举参与者及其目标；每个用例用动宾短语命名，并保证对参与者可交付价值。关系选择要克制：只有稳定复用的公共步骤才用 include；可选或条件分支才用 extend；同类参与者或同类用例才考虑泛化。检查清单包括：是否存在“登录系统”这类过细操作被当成顶层用例、是否遗漏关键外部系统、是否把实现类错画为参与者。评审时可用“一个句子说清谁为了什么目标与系统交互”作为快速验证。

## 常见误区
常见误区一是把界面按钮或页面流程直接画成用例，导致需求与 UI 绑定过紧；二是参与者与系统边界混淆，把后台服务当参与者或把用户当内部组件；三是滥用 include/extend，使图变成控制流而不是目标结构。纠正方式：回到业务目标，删掉无外部价值的技术步骤，并为每个用例补一句成功场景摘要。若学生对“包含与扩展”混淆，可先用“是否总是发生/是否可选”二分，再回到正式定义。
